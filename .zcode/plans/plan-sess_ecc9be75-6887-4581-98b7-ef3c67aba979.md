# 画布文本注释工具实现方案

## 概述

为画布新增一个 **文本注释节点**（node type `'text'`），可直接在画布任意位置放置文字作为标注，**不进入卡片库**，内容内联存储在节点 data 中（board 级），**既能发起连接也能被连接**。富文本用单段落 BlockNote（仅粗体/斜体/链接内联标记）。外观克制：透明背景、选中框、文字前一个彩色小圆点作为分类标记、文字本身永远默认前景色。

### 使用场景梳理（含本次取舍）

| 场景 | 本次是否做 | 说明 |
|------|-----------|------|
| 画布角落/区域标题注释 | ✅ 核心 | 放大字号当分区标题 |
| 给卡片组/关系做文字标注 | ✅ 核心 | 配合连接线串联多张卡 |
| 彩色小圆点分类标记 | ✅ | 10 色预设，仅圆点着色，文字保持默认色 |
| 字号预设切换 | ✅ | sm/md/lg/xl (12/14/18/24px) |
| 左/中/右对齐 | ✅ | 文本在注释宽度内对齐 |
| 被连接线连接（作终点） | ✅ | 邻近检测+点击完成 |
| 发起连接（作起点） | ✅ | 悬浮连接按钮 → connectionMediator |
| 拖拽移动 + 对齐吸附 | ✅ | 复用 useCanvasDrag 吸附、AlignmentToolbar |
| 撤销/重做、保存/加载 | ✅ | 自动接入 useHistory / useBoardSync |
| BlockNote 内联格式（粗/斜/链接） | ✅ | 单段落 schema，键盘快捷键 Ctrl+B/I/K |
| 选中框 | ✅ | 透明背景 + 选中描边 |
| **拖拽插入卡片内部** | ❌ 本次不做 | 文本注释保持画布级，边界清晰 |
| 字体族切换 | ❌ | 低 ROI，用默认 UI 字体 |
| 块级格式（标题/列表/引用） | ❌ | 注释保持单段落，刻意克制 |
| 复制粘贴文本注释 | ❌ | 后续可加 |

### 其他高 ROI 工具建议（本次不做，供后续）

1. **连接线标签（Edge Labels）** — 目前 `ConnectionEdge` 无标签。给连线加文字标签标注关系（"导致/支持/反驳"），与文本注释天然搭配，中等工作量。
2. **形状/高亮区域** — 矩形/椭圆做分组高亮，中低 ROI。

## 实现步骤

### A. 新增文件

**1. `src/components/editor/annotationSchema.ts`** — 最小 BlockNote schema
- `BlockNoteSchema.create({ blockSpecs: { paragraph: defaultBlockSpecs.paragraph } })`，仅段落块，无 heading/list/imageRow
- inlineContent 用默认（含 bold/italic/link），不挂 cardReference/tag（注释不需要 @卡片/#标签）
- 导出 `annotationSchema`

**2. `src/components/editor/AnnotationEditor.tsx`** — 精简单段落编辑器（~90 行）
- `useCreateBlockNote({ schema: annotationSchema })` + `BlockNoteView`
- 复用 `usePosAtCoordsScalePatch`（处理非 100% 缩放下的 posAtCoords，已有 hook）
- props: `content, onChange, fontSize, align, editable, onReady`
- 不挂 SlashMenu / FormattingToolbar / MentionMenu（保持克制；粗体/斜体/链接走 Ctrl+B/I/K）
- `forwardRef` 暴露 `focus()/blur()`
- 内容序列化：`JSON.stringify(editor.document)` ↔ `parseContentToBlocks`

**3. `src/components/canvas/TextAnnotationNode.tsx`** — 节点组件（~220 行，memo）
- 透明背景容器；`selected` 时 `outline: 2px solid var(--line-active)`
- 文字前一个 8px 彩色圆点（`CARD_COLORS[color].stroke`），点击圆点弹色板
- 内嵌 `<AnnotationEditor>`，`fontSize`/`align` 通过 CSS 应用
- `<CardHandles />`（复用，8 个隐形 handle 提供连接锚点）
- 悬浮迷你工具条（hover/selected 显示）：字号切换、左中右对齐、色板、连接按钮(ArrowUpRight)、删除
- ResizeObserver 自动撑高 `data.height`（参考 CardNode MiniCard 模式 63-116 行）
- 角落 `NodeResizeControl`（参考 MediaNode 90-105 行）可调宽
- 连接逻辑（复刻 CardNode.handleCardClick 177-199 行的核心）：
  - 订阅 `connectionMediator` 的 `isConnectingFrom`/`isNearbyTarget`
  - 被连接时点击 → `connectionMediator.complete(...)` 传入 source/target 尺寸
  - 连接按钮 → `connectionMediator.start(nodeId, 'top')`
- 编辑态设 `dragHandle: '.text-anno-drag-handle'` 避免拖拽与编辑冲突（参考 CardNode 118-138 行模式）

**12. `src/components/canvas/AlignmentToolbar.tsx:36`** — 对齐参与
- `isAlignableNode`：`node.type === 'card' || 'media'` → 加 `|| 'text'`

**13. `src/components/canvas/CustomConnectionLine.tsx`** — 连线绘制
- 第 50/69 行 `fromNode.data as CardNodeData` 读 width/height：text 数据有这俩字段，cast 宽松可用；为稳妥改为泛型读取 `data.width ?? DEFAULT_CARD_WIDTH`

### C. 不需要改的（已确认自动兼容）
- `connectionMediator` — 按 nodeId 索引（变量名叫 cardId 实际是 nodeId），text 节点直接用 nodeId 即可
- `useBoardSync` / `useHistory` / `useWorkspaceLifecycle` — 泛型处理 nodes/edges，text 节点自动接入；rehydration 时 text 走 `zIndex: 10` 的 else 分支
- `BoardLibraryView` 卡片计数 — 只数 `type==='card'`，注释不计入（正确）
- lasso 框选 — 只选 card 入 frame（注释不进 frame，正确）

## 风险评估

- impact 分析：`serializeBoardData`/`createCanvasSpatialIndex`/`ReactFlowCanvas` upstream 均为 **LOW** 风险
- 最大风险点：**第 6 项序列化守卫**——遗漏会导致保存重载后文本注释损坏为 card，必须改
- BlockNote 编辑器缩放兼容：复用已有 `usePosAtCoordsScalePatch`，与卡片编辑器同机制
- 性能：每个注释挂一个轻量 BlockNote 实例；annotationSchema 远小于 cardSchema（无 imageRow/mention/tag），内存开销可控
