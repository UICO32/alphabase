# 交互 UI 一致性优化设计规格

**日期：** 2026-07-18  
**状态：** 已完成方向确认，待用户审阅书面规格  
**实施策略：** 渐进式一致性治理，不进行大范围视觉重构

## 1. 背景

当前应用在宽屏下已经形成稳定的左面板、中央画布、右面板结构，也具备语义颜色、间距、圆角、动效时长等基础 token。但组件状态、浮层实现和屏幕适配仍存在局部差异：

- 约 900px 以下左右面板开始压缩画布，约 680px 以下出现明显重叠，手机宽度下主要操作区相互冲突。
- Button、IconButton、工具栏按钮、标签和列表项并未完整共享同一套 default、hover、pressed、selected、focus-visible、disabled 规则。
- Radix Dialog 与若干自定义弹窗并存，固定宽度弹窗在窄窗下缺少统一约束。
- Popover、Dropdown、Dialog、Toast 和侧面板的职责边界与进入/退出节奏不完全一致。
- 已有 token 和动画基础可以复用，不需要替换组件库或重做视觉语言。

## 2. 竞品研究结论

### The Dark Side

参考：<https://www.dark.design/>

可借鉴的不是黑色外观本身，而是低噪声的页面层级、稳定的卡片反馈、明确的分类/选中关系，以及移动端主动收敛导航和内容列数的方式。

### Pinterest 与 Gestalt

参考：

- <https://www.pinterest.com/>
- <https://gestalt.pinterest.systems/v1/web/button>
- <https://gestalt.pinterest.systems/v1/web/masonry>
- <https://gestalt.pinterest.systems/v1/web/overlaypanel>
- <https://gestalt.pinterest.systems/v1/web/popover>
- <https://gestalt.pinterest.systems/v1/web/toast>

可借鉴的核心是组件状态的可预测性、响应式网格的确定性，以及不同浮层各自清晰的任务职责。Popover 负责轻量上下文操作，Dialog 负责必须明确完成或取消的任务，Toast 只提供短暂且非阻塞的结果反馈。

## 3. 设计目标

1. 在常见桌面、窄桌面和平板/手机宽度下，中央画布始终保持可用，不再与左右面板重叠。
2. 高频组件共享可识别且一致的交互状态，同时保留现有颜色、圆角、字体和整体密度。
3. 浮层按任务类型分工，并共享遮罩、层级、焦点、关闭方式与动效节奏。
4. 动效表达状态变化和空间关系，不制造布局跳动，并完整支持减少动态效果偏好。
5. 按风险和用户价值分阶段落地，每一阶段都能独立测试和交付。

## 4. 非目标

- 不改变现有信息架构、核心业务流程或三栏工作区心智模型。
- 不重新设计品牌、主题、字体、主色或整体视觉风格。
- 不替换 Radix/shadcn 等现有基础设施。
- 不在同一轮迁移所有直接使用的原生 `<button>`。
- 不为了抽象而拆分所有大组件；只处理本轮功能需要触及的边界。
- 不引入复杂动画框架；优先使用现有 CSS token、transition 和 Radix 状态属性。

## 5. 总体方案

采用“保守外观、统一规则、渐进迁移”的混合方案：

- 视觉层保持现有表面颜色、边框、圆角和排版，仅允许小幅修正间距、边框与阴影。
- 行为层集中定义响应式外壳、交互状态矩阵、浮层职责与动效 token。
- 组件层先覆盖 App 外壳、左右面板、工具栏、卡片库和本轮涉及的浮层；其余组件后续按触达顺序迁移。
- 不建立第二套平行 UI 系统，新增规则应进入现有 `src/theme` 与 `src/components/ui` 基础层。

## 6. 响应式外壳

### 6.1 断点

| 可用宽度 | 布局模式 | 面板行为 |
| --- | --- | --- |
| `>= 1100px` | 宽屏三栏 | 左右面板可独立展开，保留用户当前状态 |
| `820px–1099px` | 中等宽度 | 最多展开一个侧面板；打开另一侧时自动收起当前侧 |
| `< 820px` | 窄窗 | 左右面板变为贴边抽屉，同时只允许打开一个 |

断点由应用内容区域的可用宽度决定。第一阶段可使用窗口宽度实现，但规则必须封装在单一响应式入口中，避免不同组件各自监听和判断。

### 6.2 窄窗抽屉

- 左面板从左侧进入，右面板从右侧进入。
- 抽屉贴边并占标题栏以下内容区域的完整高度；无外边距，不呈现居中或悬浮卡片轮廓。
- 抽屉覆盖画布，不压缩画布、不触发画布重排；关闭后画布位置和缩放保持不变。
- 默认宽度为 `min(360px, 88vw)`，保证仍能感知画布上下文。
- 使用轻量遮罩。点击遮罩、按 `Esc` 或点击明确的关闭按钮均可退出。
- 打开时焦点进入抽屉，关闭后返回触发按钮；抽屉打开期间焦点不得进入被遮挡的背景操作区。
- 如果一侧抽屉已打开，触发另一侧时直接切换，不叠加两个抽屉。

### 6.3 中等宽度面板

- 继续使用当前布局面板，不转为抽屉。
- 只允许一个侧面板展开，避免中央画布降至不可用宽度。
- 切换侧面板时保持画布中心和缩放，不通过先收起再展开造成两次布局跳动。
- 从窄窗恢复到中等或宽屏时，关闭抽屉并按当前断点恢复合法的面板状态。

### 6.4 弹窗宽度

所有 Dialog 内容使用统一的视口约束：左右保留安全间距，宽度不得超过可用视口。现有 500px、560px、600px 等固定设计宽度可继续作为 `max-width`，不能作为窄窗下的强制宽度。

## 7. 交互状态系统

### 7.1 状态矩阵

高频交互组件统一覆盖：

`default -> hover -> pressed -> selected -> focus-visible -> disabled`

其中 selected 可与 hover 或 focus-visible 同时存在，组合状态不得丢失选中表达。

| 状态 | 表达目的 | 规则 |
| --- | --- | --- |
| default | 建立常规层级 | 使用现有语义表面、文字和边框 token |
| hover | 表示可操作 | 轻微表面或文字变化，不冒充选中态 |
| pressed | 表示输入已被按下 | 使用短时明度/表面变化，可有最多 1px 位移，不做明显缩放 |
| selected | 表示持续状态 | 使用持续可见的背景、边框或强调色，不能仅依赖文字颜色 |
| focus-visible | 表示键盘焦点 | 统一语义 focus ring，不在鼠标点击后长期显示 |
| disabled | 表示不可用 | 降低对比度并禁用 hover/pressed；保持文字可读，不仅依赖透明度 |

### 7.2 首批覆盖组件

- `Button`、`IconButton`
- 顶部 Toolbar 中的高频按钮
- 左右面板的标签、入口和折叠控制
- CardLibraryView 的筛选、排序、标签和列表项
- 本轮修改涉及的分段控件和菜单触发器

不要求第一阶段清理全仓库所有原生按钮。只有在触及某个高频区域时，才迁移到共享 primitive 或共享状态类。

## 8. 浮层职责与统一形式

| 类型 | 使用场景 | 不用于 |
| --- | --- | --- |
| Dialog | 必须明确完成、确认或取消的任务 | 快速筛选、轻量设置 |
| Drawer | 窄窗中的左右侧面板 | 桌面普通弹窗 |
| Popover | 与触发器强关联的轻量选择或设置 | 破坏性确认、复杂主任务 |
| DropdownMenu | 紧凑命令列表 | 多字段编辑 |
| Tooltip | 解释图标或简短含义 | 承载按钮、输入或必要信息 |
| Toast | 短暂、非阻塞的结果反馈 | 需要用户决策的错误或确认 |

统一内容包括：

- 遮罩透明度与层级关系。
- 表面、边框、阴影与允许的小范围圆角差异。
- `Esc`、外部点击、关闭按钮的行为约定。
- 初始焦点、焦点约束和关闭后的焦点回收。
- 进入/退出时长与 easing。
- Toast 同时只显示一个；信息保持简短，不堆叠通知。

迁移采用渐进方式：先统一共享基础和本轮涉及的高频浮层，不一次性重写所有自定义弹窗。

## 9. 动效系统

### 9.1 时长

| 场景 | 建议时长 |
| --- | --- |
| hover / pressed | `100–140ms` |
| 控件状态切换 | `140–180ms` |
| Popover / Dropdown | `140–180ms` |
| Drawer / Dialog | `180–240ms` |
| 面板尺寸变化 | 约 `200ms` |

具体数值应复用或收敛到现有 duration/easing token，不为单个组件制造新的近似值。

### 9.2 动画属性

- 优先动画 `transform` 与 `opacity`。
- 仅在面板布局确实变化时动画尺寸；避免在同一过渡中同时修改多个会触发布局的属性。
- 抽屉从所属边缘进入，Popover 从触发器方向轻微位移进入，Dialog 使用短距离淡入；动画必须表达空间来源。
- 不使用大幅弹跳、持续呼吸或装饰性循环动画。
- `prefers-reduced-motion: reduce` 下关闭位移和缩放，仅保留必要的即时或极短淡化反馈。

## 10. 可访问性与输入方式

- 所有仅图标控件必须有可访问名称。
- 键盘用户能打开、操作并关闭 Dialog、Drawer、Popover 和 Dropdown。
- 选中态使用 `aria-pressed`、`aria-selected` 或对应 Radix 状态语义，不只依赖颜色。
- Hover 信息不能成为唯一信息来源；触屏和键盘均需获得等价反馈。
- Dialog 和 Drawer 打开时管理背景可交互性与焦点范围。
- disabled、focus ring、文字与背景对比度在现有主题中保持清晰。

## 11. 分阶段实施顺序

### P0：响应式外壳

1. 建立单一断点入口与布局模式。
2. 实现中等宽度面板互斥。
3. 实现窄窗左右贴边抽屉与焦点/遮罩行为。
4. 将固定宽度 Dialog 改为视口安全的最大宽度。
5. 验证 1280px、900px、680px、480px 视口。

### P1A：高频状态统一

1. 收敛 Button、IconButton 状态。
2. 迁移 Toolbar 高频按钮。
3. 迁移左右面板标签和入口。
4. 迁移 CardLibraryView 的筛选、排序和列表项。

### P1B：浮层基础统一

1. 统一 Dialog/Popover/Dropdown/Toast 的表面和动效 token。
2. 统一关闭方式与焦点回收。
3. 迁移本轮涉及的自定义弹窗，不扩大到低频无关模块。

### P2：动效与细节校准

1. 清理重复或相互冲突的 transition。
2. 完善减少动态效果模式。
3. 小幅校准间距、边框和阴影。
4. 消除面板切换和浮层关闭时的布局跳动。

## 12. 验收标准

### 响应式

- 1280px 下维持现有三栏体验，无明显视觉改版。
- 900px 下左右面板不会同时挤压画布。
- 680px 与 480px 下左右入口不重叠，面板以对应边缘抽屉出现。
- 打开或关闭窄窗抽屉不会改变画布的中心、缩放和内部尺寸状态。
- 所有 Dialog 在 480px 下保留安全边距且内容可访问。

### 状态

- 高频组件的 default、hover、pressed、selected、focus-visible、disabled 均可辨识。
- selected + hover、selected + focus-visible 等组合状态仍保留选中表达。
- 鼠标、键盘和触摸输入不依赖某一种专属反馈才能完成任务。

### 浮层与动效

- 同一时间最多出现一个窄窗侧抽屉和一个 Toast。
- Dialog、Drawer、Popover 均支持预期的 `Esc` 与焦点回收。
- 常规模式下动效方向与空间来源一致，无明显跳帧或布局抖动。
- reduced-motion 下不出现抽屉位移、缩放或非必要动画。

### 回归验证

- 运行与修改文件相关的 TypeScript、ESLint 和单元测试。
- 使用 Playwright 或现有浏览器验证覆盖 1280、900、680、480 四档视口。
- 覆盖左右面板切换、弹窗开关、键盘焦点、Escape、外部点击与 reduced-motion。
- 在每一实施阶段结束时单独验证，避免等到全部迁移后才发现回归。

## 13. 风险控制

- App 外壳和面板状态属于共享路径，实施前必须使用 GitNexus 对待修改符号逐个执行上游影响分析；若风险为 HIGH 或 CRITICAL，需先向用户报告再修改。
- 工作区当前存在用户的其他改动。实施必须使用定向编辑和定向验证，不覆盖或回滚无关文件。
- 响应式状态与持久化面板状态可能冲突。布局模式只决定当前允许呈现的状态，不应意外覆盖用户的宽屏偏好。
- 浮层迁移可能影响焦点和快捷键。每迁移一种浮层都应先补充对应行为测试，再替换实现。
- 提交前运行 GitNexus `detect_changes`，确认影响仅落在预期组件和执行流。

## 14. 已确认决策

- 采用渐进式一致性治理，不进行大范围重构。
- 不显著改变现有视觉 UI。
- 窄窗侧面板使用贴边抽屉，不使用带外边距的临时悬浮覆盖层。
- 抽屉覆盖画布且不触发画布重排。
- 先完成响应式外壳，再处理高频状态、浮层和动效细节。
